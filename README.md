# 团队知识库 (Team Knowledge Base)

团队唯一的文档知识库。基于 **Obsidian** 管理，用 **GitHub** 作为文件管理与协作中枢，团队成员通过 **Obsidian Git 插件** 自动同步。

> 🌐 **站点**：<https://sunlingfeng70.github.io/team-knowledge/>
>
> ⚠️ **本仓库为公有仓库**：任何人可读。**绝不提交**密钥、密码、Token、内部敏感数据。
>
> 🚦 **发布已改为手动**：push 不再自动上线。需要发布时到仓库 **Actions → Deploy Quartz site → Run workflow**。

## 🧭 目录结构

仓库根同时是 **Obsidian Vault** 和 **Quartz 发布工程**。

```
team-knowledge/
├── 00-个人区/                    ★个人区（发布源之外，结构上不会被公开）
│   └── <你的名字>/
│       ├── 随手记……
│       └── _去向.md             AI 每次把内容搬进正式区后，在这里追加一行
│
├── 01-公共区/                     ← Quartz 内容源（这里的都会公开）
│   ├── index.md                 首页导航
│   ├── 10.领域知识/             可复用的领域知识
│   │   └── 01.研发/  02.业务/  03.运维/
│   ├── 30.项目/                 具体项目的产物
│   ├── 40.参考/                 工具、规范、外部资料
│   ├── 90.归档/                 失效但留档的内容
│   ├── _templates/              文档模板（不发布）
│   └── _附件/                   图片与附件统一存放（必须发布，否则全站图挂）
│
├── quartz/  package.json  …     Quartz 构建引擎（**必须保留**，构建站点靠它）
└── 已 ignore，绝不进仓库：
    ├── .scratch/                内部设计草案（含内网架构）
    ├── copilot/                 Copilot 技能包（AI 工具本地配置）
    ├── CONTEXT.md               内部治理口径
    └── **/.obsidian/  **/.claudian/   本机配置与会话记录
```

> **两个目录的编号**：`00-个人区` 与 `01-公共区` 是并列的两区，编号只表示「先个人、后公共」。
> Quartz 只读 `01-公共区/`，`00-个人区/` 在它视野之外——这是硬边界。

### 两张表：每个目录怎么用

**正式区 —— 会公开**

| 目录 | 放什么 | 谁能写 |
| --- | --- | --- |
| `10.领域知识/01.研发/` | 架构与设计、技术调研、接口与数据、故障与复盘 | 所有人 |
| `10.领域知识/02.业务/` `03.运维/` | 业务知识、运维知识 | 所有人 |
| `30.项目/<项目名>/` | 项目产物、过程文档 | 项目成员 |
| `40.参考/` | 工具用法、规范、外部资料 | 所有人 |
| `90.归档/` | 已失效但值得留档的内容 | 园丁（其他人只读） |
| `_附件/` | **所有**图片与附件 | 所有人 / AI |
| `_templates/` | 模板 | 园丁 |

**个人区 —— 不会公开**

| 目录 | 放什么 | 谁能写 |
| --- | --- | --- |
| `00-个人区/<你的名字>/` | 随手记。思考过程、会议速记、调研碎片、半成品 | **只有本人** |

> **写进个人区就等于声明"这条准备给团队看"。** 所以私事、牢骚、内部人事、客户敏感信息**不要放这里**。
> AI 会把成型内容搬进正式区（移动，不留副本），并在你的 `_去向.md` 里留一行记录。

## 🚀 新成员 5 步上手

### 1. 安装 Obsidian

到 <https://obsidian.md> 下载安装。

### 2. Clone 仓库并作为 Vault 打开

```bash
git clone https://github.com/sunlingfeng70/team-knowledge.git
```

在 Obsidian 中：**Open folder as vault** → 选择刚 clone 的**仓库根目录**（不是 `01-公共区/`）。

> 仓库根打开时，`00-个人区`（个人区）和 `01-公共区`（正式区）都能看到。
> 想少看几个技术目录，可以把 `quartz`、`node_modules`、`copilot` 加进 Obsidian 的「排除文件」设置。
### 3. 启用 Obsidian Git 插件

仓库已自带该插件配置，若未启用：设置 → 第三方插件 → 启用 **Obsidian Git**。

### 4. 配置访问令牌 (PAT) 与自动同步

1. 在 GitHub 生成 **fine-grained PAT**（仅本仓库 Read/Write 权限）：
   GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token → 勾选本仓库 Content: Read/Write。
2. 在 Obsidian Git 插件设置里填入认证（HTTPS + PAT）。
3. 设置自动备份间隔 `Auto backup interval (minutes)` = **10**，自动拉取间隔 `Auto pull interval (minutes)` = **10**。

> 更细的图文步骤（含 Mac SSH 方式）见 [[Obsidian Git 配置方法]]。

### 5. 开始记录

**把东西丢进 `00-个人区/<你的名字>/`，其他什么都不用管。**
分类、命名、加字段、建链接、收附件，全都不是你的活——AI 会做。

写得正式的内容也可以**直接写进正式区**。不确定放哪就丢个人区。

## 📐 命名约定

- **文件名说人话**，让一眼看懂它讲什么。别用 `新建文档 1`、`未命名`。
- **不加日期前缀**。日期交给 frontmatter 的 `created`，文件名只放主题。
- 图片不用管命名，AI 会统一收进 `_附件/`，正文用 `![[文件名]]` 引用。

## 📝 frontmatter 契约

正式区的文档由 AI 统一补全这些字段（你手写时补不补都行）：

| 字段 | 说明 |
| --- | --- |
| `title` | 标题 |
| `type` | 类型：`note` / `project` / `meeting` / `decision` / `howto` / `research` … |
| `topic` | 所属知识线，如 `研发/架构与设计`、`项目名/阶段` |
| `tags` | 标签 |
| `created` / `updated` | 创建 / 更新日期 |
| `aliases` | 别名（让别的笔记能用不同说法链过来） |
| `status` | `draft` / `active` / `outdated`（`draft` 不会发布） |
| `owner` | 内容负责人 |
| `source` | 来源（会议、链接、谁说的） |

## 🤝 同步三原则

1. **先 pull 再编辑**：开始编辑前先同步（Obsidian Git → Pull）。
2. **小步提交**：改完及时提交，不要攒一大批。
3. **避免同文件并发编辑**：和他人同时改同一文件会产生**合并冲突**。协作前先沟通，或错峰编辑。

### 遇到合并冲突怎么办？

- Obsidian Git 插件会在状态栏提示冲突。
- 打开冲突文件，`<<<<<<<` / `=======` / `>>>>>>>` 之间是需要手动取舍的内容。
- 保留正确内容、删掉标记行，保存并提交。
- 不确定时**找技术同学协助**，切勿乱删内容。

## 🔒 安全红线

- 本仓库**公有可见**，禁止提交：API 密钥、密码、Token、内部敏感信息。
- 写文档举 `KEY=xxx` 这类例子时，**一律用占位符**，不要贴真 key。
- 误提交敏感信息后，仅删除文件不够，需按 GitHub 官方流程**历史清理**并**轮换该凭据**。
