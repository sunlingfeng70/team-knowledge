原因已经很明确：这次不是“封面生成质量不好”，而是图片生成工具根本没有拿到图片生成 API Key，调用在真正请求模型之前就失败了。

截图中的关键错误是：

> ```
> Missing image generation API key
> ```

对应后端代码在 [runtime.py (line 283)](K:/works/028.数产尖刀班/.research-screenshot-to-code/backend/agent/tools/runtime.py:283)：

```
replicate_api_key = self._effective_replicate_api_key()
if not replicate_api_key:
    return ToolExecutionResult(
        ok=False,
        result={"error": "No API key available for image generation."},
        summary={"error": "Missing image generation API key"},
    )
```

这个工具使用的是 Replicate 图片生成服务，需要配置：

```
REPLICATE_API_KEY=你的 Replicate API Key
```

而不是：

```
OPENAI_API_KEY=...
OPENAI_BASE_URL=https://api.deepseek.com
MODEL_NAME=...
```

你现在配置的 DeepSeek/OpenAI 兼容 Key，只能用于文本模型生成代码，不能自动作为图片生成服务的 Key。项目配置中两者是分开的：

[config.py (line 9)](K:/works/028.数产尖刀班/.research-screenshot-to-code/backend/config.py:9)

```
GEMINI_API_KEY = os.environ.get("GEMINI_API_KEY", None)
OPENAI_BASE_URL = os.environ.get("OPENAI_BASE_URL", None)
REPLICATE_API_KEY = os.environ.get("REPLICATE_API_KEY", None)
```

功能对应关系是：

| 功能                              | 使用的 Key                          |
| --------------------------------- | ----------------------------------- |
| GPT、DeepSeek 等文本模型生成 HTML | `OPENAI_API_KEY`、`OPENAI_BASE_URL` |
| Gemini 视觉资产提取               | `GEMINI_API_KEY`                    |
| Replicate AI 图片生成             | `REPLICATE_API_KEY`                 |
| Replicate 图片编辑、抠图          | `REPLICATE_API_KEY`                 |

“Generated 4 images”为什么还会显示？

这是前端状态标题的一个表现问题。前端在 [AgentActivity.tsx (line 208)](K:/works/028.数产尖刀班/.research-screenshot-to-code/frontend/src/components/agent/AgentActivity.tsx:208) 中这样计算数量：

```
const count = output?.images?.length || input?.count || 0;
```

这次工具输入里有：

```
{
  "count": 4,
  "prompts": [...]
}
```

虽然后端返回了错误，没有真正生成任何图片，但前端因为 `output.images` 不存在，就退回使用输入中的 `count: 4`，于是界面显示成：

```
Generated 4 images
```

所以这句话并不代表四张图片已经成功生成。展开后看到红色错误框，才是实际结果。

后面的模型说明：

> The cover generator is unavailable in this environment, so I'm using stable ISBN cover endpoints...

也是模型根据工具失败结果做出的降级策略。它没有可用的 Replicate 封面生成服务，于是选择了 OpenLibrary 的 ISBN 封面地址，例如：

```
https://covers.openlibrary.org/b/isbn/9780060883287-L.jpg
```

这就解释了你之前看到的现象：

- 图片没有保存到 `生成的代码` 目录；
- HTML 中使用的是网络图片 URL；
- 《百年孤独》变成了英文版封面；
- 生成页面和原始截图中的中文封面差异很大。

这次实际流程是：

```
截图
  ↓
模型识别出需要 4 张封面
  ↓
调用 generate_images
  ↓
缺少 REPLICATE_API_KEY，调用失败
  ↓
模型选择 OpenLibrary ISBN 外链作为替代
  ↓
生成 HTML
```

因此，目前的核心问题不是 DeepSeek 模型不会生成图片，而是：

1. DeepSeek 只负责文本和代码生成；
2. `generate_images` 工具依赖 Replicate；
3. 你的环境没有配置 `REPLICATE_API_KEY`；
4. 项目允许模型在图片工具失败后自行寻找外部图片；
5. 前端标题错误地把“请求数量”显示成了“成功生成数量”。

如果希望封面更接近原图，有三种路线：

1. 配置 Replicate：

   ```
   REPLICATE_API_KEY=...
   ```

   这样可以使用项目的 `generate_images` 工具，但 AI 生成的书封面仍然不保证和原图一致。

2. 配置 `GEMINI_API_KEY`，让项目调用 `extract_assets`，从原始截图中裁剪出书封面。这个方案更接近原图，因为它使用的是截图里的真实图片，而不是重新生成。

3. 修改系统提示和工具策略：要求模型优先提取原图资产；提取或生成失败时禁止自行使用 OpenLibrary、Unsplash 等外部图片，只能使用本地裁剪图或明确显示占位图。

对你这个场景，第二种方案最适合。因为你想复刻的是已有页面，书封面属于原始视觉资产，应该从截图中提取，而不应该让模型重新绘制或根据书名搜索一个可能不同版本的封面。
